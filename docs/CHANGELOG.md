- **What:** Batch 3a, urgent data-safety fixes from the owner's real iPad Pro (Safari app, Pencil Pro, Scribble on). **1. A Pencil drag over text deleted it.** Most likely cause: iPadOS Scribble reads a Pencil stroke over editable text as handwriting or scratch-out, and the change can arrive as `delete*`, `insertReplacementText`, a composition, or a plain DOM change with no `beforeinput`; the 2f guard only looked at `delete*` for 300 ms, and the stroke was still given to the browser. This cannot be proven without the iPad. Fix, in layers: (a) new `penSelect.ts`: a Pencil stroke that starts on text is handled by us. The pointer events are cancelled, Safari's stylus touchstart/touchmove are cancelled (a finger still scrolls; CSS `touch-action` cannot tell pen from finger), the page is made not editable for the length of the stroke so Scribble has nothing to write in, the selection is set from the Pencil position (`posAtCoords`) in ProseMirror and the browser, then the page is editable and focused again. A double tap selects a word. A stroke that reaches a picture is left to `dragSelect.ts`. (b) `penGuard.ts`: the `beforeinput` guard now also refuses writing (insertText, replacement, composition) while a Pencil gesture that began in the page is active or ended less than 500 ms ago; a ProseMirror `filterTransaction` rejects any transaction that removes or replaces content in that window (Undo/Redo and real key presses are exempt; taps on the bar or menus begin outside the page text, so Delete from them still works). (c) New setting Settings › Advanced › **Pencil writes text (Scribble)**, off by default, with a Scribble note; on = the browser handles the Pencil as before. **2. Undo/Redo and lost pictures.** Findings: picture files are never deleted (blocks are soft-deleted and pictures stay in `images`; no cleanup code exists), so a restored picture block always finds its file. The real gaps were: History took no copy before a big delete (a copy is made at most every 5 minutes, so a delete soon after one could not be recovered); the bar's greyed Undo state could be stale; and the bar commands depended on editor focus. Fixes: `pageSync.ts` forces a History copy of the saved page before saving a delete of 3 or more blocks or of any picture block (`isBigDelete`); new `historyActions.ts` runs Undo/Redo on the editor view itself and then focuses it (bar, ribbon, control panel and the Undo messages use it); the bar re-reads its Undo/Redo state every 400 ms.
