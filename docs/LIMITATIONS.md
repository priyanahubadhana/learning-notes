# Known Limitations

- **AI (bring your own key):** the key sits unencrypted in this browser's localStorage (a web page cannot encrypt it without a passphrase); it is never in a backup or sync, so each device needs the key again. Answers are not streamed (nothing shows until done). Handwriting reading is as good as the chosen model; Hindi needs a vision model (Haiku 5.5 reads it). Pen-pressure weights need a real pen: a mouse or finger gives every word the chosen weight. Prices are a dated table, not live.

- **Pages can't be dragged** in the sidebar tree (notebooks can).
- **Safari on Windows is slow in tests:** run WebKit tests with `--workers=2 --timeout=120000`. One touch-drag test runs only in Chrome. Two WebKit tests still fail on robot typing and selecting in the editor; the owner confirmed both features work on the real iPad. Look and feel on real devices is checked by hand.
- **First load size:** 349.6 KB gzipped on 2026-11-07 (limit 350 KB, checked by `npm run check:size` in CI); almost no spare room, so new code on the first screen must load on demand.
- **Hindi editor menus:** BlockNote has no Hindi menus yet.
- **Spanish and Hindi** need native-speaker review.
- **Data lives in one browser:** no sync yet; move it with Save everything and Open saved file.
- **Delete forever keeps pictures:** page history is erased, but no code in Trash erases picture files. Fix before sync.
- **Same-spot inserts:** two devices adding a block at the same spot get the same order key, and a later insert between them fails. One window per page now prevents this on one device; fix before sync (see RESEARCH.md).
- **Ink in shared files:** page and notebook sharing and "Add as copies" do not carry drawings yet (step 10). Backups and History copies do.
- **Ink on very long pages:** all strokes of a page load at once (drawing only the visible part); lazy chunk loading comes later.
- **Replace from older files:** a full save made by an older database version from before version 12 cannot replace the notes (it can be added as copies); version 12 files can (13 only added tables). Bringing older rows through the upgrade steps is still to do. Restoring holds the whole file in memory while checking it.
- **Formatting bar on touch:** the docked bar is built from tests and screenshots in Chrome; how it feels with the real iPad keyboard, the iPad shortcut bar and the Pencil is checked by hand. The bottom bar rises with the keyboard through the browser's visual viewport, which Safari reports a little late. Hover tips and shortcut hints apply to the docked bar only.
- **Two windows:** a read-only window does not refresh by itself, and page titles are not locked.
- **Update bar:** tested by unit tests only; a real update is the first full check.
- **Manual upload:** Cloudflare cannot turn it off, so a daily check catches it instead.
- **Selecting across pictures:** a Pencil or mouse drag selects whole blocks including pictures; a finger drag still scrolls (the browser's long-press selection and handles are unchanged and may skip a picture). Tested with simulated pen events, not the real Pencil.
- **Apple Pencil and Scribble (batch 3a):** a Pencil stroke on text selects only; the page is made not editable during the stroke and Scribble writing or scratch-out is refused for 500 ms after it. Built from how iPadOS behaves and tested with simulated pen events; whether the real Scribble obeys, and whether Safari honours the stylus touch cancel, is checked on the iPad. The on-screen keyboard may flicker after a stroke. Handwriting to text is opt-in (Settings › Advanced › Pencil writes text).
- **Undo and History:** pictures are never deleted from the device, so Undo can always bring a picture back. History keeps a copy before a delete of 3 or more blocks or any picture, but only the newest 30 copies per page.
- **Slim ribbon and long names:** Slim shows icons only, with names in the tooltip and as accessible labels; a finger has no hover, so the control panel search is the way to see every name.
- **Floating bar:** it follows the visible screen when the keyboard opens (visual viewport), tested here with window resizes; the real iPad keyboard, rotation and Pencil drag are checked by hand.
- **Privacy lock is not encryption:** a locked page is hidden in the app, but its text is still in the browser's storage unencrypted; an expert with the device can read it or clear the lock. A 4–6 digit PIN is weak whatever the hashing. Real encryption comes with Phase 10.
- **Lock and the app switcher:** the app blanks itself when it goes to the background, but iOS decides when it takes its snapshot; checked by hand on the iPad. The device lock (Face ID) works only on the device it was set up on and is not in backups.
- **Reading mode:** paged reading is in the full-screen reader only (in place a page scrolls). Read aloud uses the device's voices: word marks need a voice that sends word events and Safari 17.2 or later (otherwise the sentence is marked); a locked screen can stop speech, and the app starts the sentence again when it comes back. Resume and bookmarks stay on one device.

- **What a web app cannot match from native PencilKit apps (GoodNotes, Notability):** very low-latency ink (a browser adds a frame or two, even with pointer prediction), palm rejection by the system, and system Scribble integration (handwriting into any field, scratch-out, the Scribble palette). Instead: the Pencil follows the active tool (free for Scribble under Text, hold-to-select, double and triple tap selection, a mini toolbar instead of the iOS callout), a guard against big scratch-out deletes with Undo, and the ink engine (step 3) draws with pointer events and prediction. If that is not smooth enough on the owner's iPad, a native shell (PencilKit) is the later option. Not provable without a real iPad.
- **Audio recording:** one recording at a time; held in memory until Stop (a full device loses it); iPadOS stops it when Safari goes to the background; not in single-notebook files or Add as copies; no ink replay, rename or lock-screen player yet; "Notes only" backups leave the sound out.
- **Still "coming" in the bars:** Insert items Table, Shape, Camera, File, Tape, Magnifier and Ruler, Toggle list (master plan G1–G2), and the Lasso extra Save to notes (A2). Convert to text is built (Phase P) and needs the user's own AI key. The ink engine itself is built (step 3) and Phase A is making the Pencil trustworthy on the real iPad.
