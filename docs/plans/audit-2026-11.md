Who: the auditing model (Opus), while a Sonnet builder works on Phase A. What was read: CLAUDE.md, every `rules/` file, INDEX, HANDOFF, ROADMAP, DECISIONS, CHANGELOG, LIMITATIONS, IDEAS, CODE-MAP, the four `docs/plans/` files, all `docs/research/`, the feature specs, `git log -80`, the Phase A part 1 diff, the Dexie schema, the settings and tool registries, the e2e list, `npm run build`, `npm test`, `npm audit`. Nothing in `src/` was changed by this audit.

**Yardstick (owner, 6 Nov, during the audit):** a practical learning experience (_anubhav_, learning by experiencing). Today people lose half their time making notes. The app should **make the notes** (automatically where possible, mostly through AI and bring-your-own-AI later) so the user's time goes to **consuming, understanding and recalling** (spaced review, memory techniques). Sources by priority: YouTube, books/PDFs and websites; then courses and lectures. Notes stay the core, made two ways: automatic, and fully manual in the "Ali Abdaal GoodNotes" style (edited pictures, labels, tape, YouTube screenshots and embedded videos with timestamps, handwriting mixed with typing, short keyword notes). Audience: anyone who wants to learn well; built to scale.

## 1. Verdict in short

- **Direction: mostly right, with one structural gap.** The foundation (one core of notebooks → pages → blocks, services, soft deletes, Dexie upgrades, FSRS review, a shared ink engine, the four spaces) is the right shape for "a beautiful building", and the code is unusually disciplined for its age (979 unit tests, 94 browser specs, 3 `any`, no `console.log`, no TODOs, every string through `t()`). Phase A (Trustworthy Pencil) is the right first phase and its research is sound; **do not pause it**.
- **The gap:** the master plan has no _capture → notes → recall_ pipeline. Nothing in Phases A–K captures from YouTube, websites or pasted text; the Library is books only; "highlight → card" exists only as a manual "Make card" button in C4; AI (the owner's main route to automatic notes) sits at Phase P after Sync, although a bring-your-own-key AI needs no server and can run from the browser today. The plan also spends more sessions on reading comfort (B1–B4, C5, H) than on recall (E1–E2), while learning research rates practice testing and spaced practice as the highest-utility techniques and highlighting, rereading and summarising as low utility ([Dunlosky et al. 2013](https://www.psychologicalscience.org/?p=82680), [Kent State summary](https://www.kent.edu/node/230016)). Highlighting earns its place only when it feeds recall.
- **What to change (section 6):** add a **Phase CR, Capture → Recall** (sources and a capture inbox; **one notes format that any AI can fill** ("Copy prompt" → paste the answer → a finished page with key points, workflow steps, cards, a mind map and screenshot slots), one-tap cards from highlights and a daily highlight review; bring-your-own-AI v0 gated on the owner's cost OK), prepare its data model inside C1 now, add the **embed** block, the **picture editor** (crop, corner resize, zoom, cut out, rotate, arrows and ink) and the **mind map** block the manual style needs, pull them into wave 3, push C5 and H2 later. Phase order otherwise stays.
- **The owner's YouTube flow today** (watch → paste link into Gemini → paste notes into Notion/GoodNotes → rewatch for screenshots → draw mind maps) maps onto the app like this: steps 2–3 become CR2 (prompt out, notes in, ₹0 now, the user's own AI); step 4 becomes the embed block with "Insert timestamp" and pasted screenshots (automatic key frames need a PC helper or a server: later); step 5 becomes the mind map block plus ink; cards fall out of the same import. Nothing in that chain needs money.

### 6a. Data model prepared in C1 (optional fields, no new Dexie version)

```ts
// Page (replaces the planned Page.book)
source?: {
  kind: 'book' | 'article' | 'video' | 'audio' | 'file' | 'paste'
  format?: 'pdf' | 'epub' | 'docx'      // books and files
  fileId?: string                        // bookFiles row
  url?: string                           // article, video, audio (https only, validated)
  author?: string
  coverImageId?: string
  pageCount?: number
  durationSec?: number                   // video, audio
  progress?: number                      // 0–1
  at?: string                            // locator: pdf:<page>:<y> | epub:<cfi> | time:<sec> | block:<id>
  openedAt?: number
  capturedAt?: number                    // when the text was captured
}
// Annotation.anchor gains
| { type: 'time'; seconds: number; endSeconds?: number }   // video and audio
// Annotation gains
cardIds?: string[]                        // cards made from it (one-tap recall)
// Card (recall) gains
sourceAnnotationId?: string               // jump back to the spot
```

Everything the C1 step says about books stays; only the field name and the kinds widen. `checkRows.ts` validates the new fields; `url` must be `https:`.

### 6a′. Principle: AI output is ordinary content (owner, 6 Nov)

Everything an AI makes (notes, summaries, database rows, mind maps, cards, pictures) arrives as the **same blocks and records a hand makes**: no locked or special "AI block", editing is identical, and one step removes a whole AI result. The data model already supports this: `Block.source` is an open string (`'ai'`), `Block.derivedFrom` exists, the mind map block is a JSON tree (editable structure, never a picture), cards are normal Card blocks with normal records, pictures are normal `images` rows. Two small additions: `Block.batchId?: string` (one AI result = one batch; also set on the cards' blocks and remembered for the images it brought) and a **"Remove this AI result"** action = `softDeleteMany` of every block, card and picture of that batch in one transaction with one Undo (Trash restores them together, as it does today). Database rows made by AI are ordinary rows (`rowRefs`/pages with `source: 'ai'`). Nothing about an AI result is read-only.

### 6b. New Phase CR — Capture → Notes → Recall (after C4; four sessions)

**CR1 · Sources and the Capture inbox.** A **Capture** route `#/capture?url=&title=&text=` and a Capture button (Library and the quiet corner): paste or type a URL, a transcript or an article; the app makes a **source page** in a "Sources" notebook (kind `sources`, like Books) with the text as normal blocks (sanitised through `sanitizePastedHtml`), the URL in `Page.source`, and for YouTube links the video id and a start time. The Library gallery shows **all sources** (filter chips Books · Videos · Articles · Pasted). **Ways in, all ₹0:** paste (PC and iPad); drag a text/HTML/URL onto the Library (PC); an **iOS Shortcut** the app offers for download ("Send to Learning Notes": takes the share-sheet text or URL and opens the installed app's capture address), because Safari has no Web Share Target ([research note, Dec 2025](https://tangled.org/zzstoatzz.io/plyr.fm/blob/main/docs/research/2025-12-19-web-share-target-ios-pwa.md)); a **bookmarklet** for PC browsers (selected text + URL). **Honest limit:** a web app cannot fetch a YouTube transcript or most article bodies itself (CORS; verified by the search in this audit), so CR1 captures what the user pastes or sends; automatic fetching needs either a browser extension (PC, later, ₹0) or a tiny Cloudflare Worker proxy (₹0 on the free tier; hosting is allowed; **ask the owner before adding a server component**). Settings › Capture explains this in two lines.

**CR2 · Notes from your own AI (one format, ₹0).** The bridge between "paste the link into Gemini" and a finished page. (1) A **Learning Notes Markdown** format (`docs/features/ai-notes-format.md`, versioned `ln-notes/1`): a title line, `## Key points`, `## Steps` (numbered workflow), `## Mind map` (an indented bullet tree), `## Cards` (`Q:` / `A:` pairs; `Cloze:` lines), `## Screenshots` (`[12:34] what to capture` slots) and free sections; pictures as `![caption](images/x.png)`. (2) **Copy prompt** on the Capture screen and on any source page: the app writes a prompt that holds the video or page link (or the pasted transcript), the format spec and the user's own extra instructions (saved as prompt presets, e.g. "Photoshop tutorial: name every tool icon"). The owner pastes it into Gemini, Claude or Claude Code. (3) **Paste notes** (or drop a zip with `notes.md` + `images/`): the importer parses the format (Markdown through `mapping.ts`; cards become Card blocks with records; the mind-map tree becomes a mind-map block once G0b exists, until then a nested list; screenshot slots become placeholder lines "📷 12:34 …" that accept a pasted picture; every block gets `source: 'ai'`/`derivedFrom` so AI-made content is marked), into the source page from CR1. (4) A **Claude Code recipe** (`docs/recipes/notes-from-video.md`): a PC-side script the owner's Claude Code can run with free tools (`yt-dlp`, `ffmpeg`) to fetch the transcript, grab frames at the moments the notes mention and zip them with `notes.md`, so "key frames at the right moments" works today on the PC at ₹0; the iPad imports the zip. Automatic frames inside the app wait for a native shell or a server. CR4 (BYO key) uses the same format, so the AI side is swappable (owner principle: a universal AI connector layer).

**CR3 · One-tap recall.** On any highlight or annotation (reader selection pop-up and the annotations panel): **Make card** (cloze of the highlighted sentence by default; Q/A when the annotation has a note: note = question, quote = answer), **Make cards from all highlights of this page** (preview list, untick, one Undo), each card linked to its annotation (`sourceAnnotationId`) and shown with "from: Source › chapter" on the review screen (tap jumps with B2's landing glow). **Daily highlight review** tile on Review home (Readwise-style: five highlights a day, oldest-unseen first, "Make card" and "Save to notes" on each). **Look up → Add to vocabulary** (from C5) lands here. Source-linked cards obey E1's decks ("Books" and "Sources" collections). Cards made by CR2's import are the same kind of card, so one review covers both.

**CR4 · Bring-your-own-AI v0** (only after the owner's explicit cost OK; off by default). `src/ai/`: `provider.ts` (interface `AiProvider { notesFrom(input, preset): Promise<string /* ln-notes/1 */> }` plus `summarise`, `cardsFrom`), `anthropic.ts` (first provider; browser calls with the `anthropic-dangerous-direct-browser-access` header; model and max tokens from a small table; the SDK is not needed, plain `fetch`), `openaiCompatible.ts` (second), `keyStore.ts` (device setting, never synced, never in backups, shown masked, "Forget key"), `usage.ts` (tokens and an estimated cost per month with a cap the user sets). Actions: **Summary** of a source page (into its Summary section), **Cards from highlights** and **Cards from this page** (an approval list, each card marked `origin: 'ai'`, one Undo), **Key points** (short keyword notes block). Per-notebook "Allow AI" switch (off), listed in Settings › Permissions; only the chosen text is sent; a one-time privacy sheet. CSP `connect-src` gains `https://api.anthropic.com` (and the second provider's host) only. MCP, connector packages and the local bridge stay in Phase P (they need a public endpoint or the PC bridge). No app-side spend: the user's own key pays.
