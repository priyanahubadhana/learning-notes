# Owner bug batch 2 (10 Nov 2026, evening iPad test of 1366af1)

Collected during the owner's test pass; fix together when the owner says so.

1. **"Changed on two devices" bar keeps appearing on every page** (screenshot: "The other version: On" above a box whose text is "Okv ' / . v 3 / On get text"). Coordinator's first look at the cause (src/sync/merge.ts `mergeRecord` + `differentText`): a clash is raised whenever the local block is dirty and the losing side has any text the winner lacks. While typing (or with the PC also open on the same page), the other device's copy is just an earlier, shorter state of the same line ("On" vs "On get text"), so every live-sync round makes a "clash". Fix ideas to verify: treat the loser as no clash when its text is a prefix/subset of the winner or an older version from this same device (same origin device id), and only when the two sides were edited independently since the last common version (needs a base/parent version check, i.e. a real three-way check); never raise one for our own echo; rate-limit to one bar per page per session. Add e2e: type on two simulated devices sequentially (no real conflict) → no bar; true simultaneous different edits → one bar.
2. **Pencil taps on a dialog draw ink instead of pressing the button** (screenshot: "Name your page" sheet; tapping Done with the Pencil left a red pen stroke over the Done button, and the page wasn't named). The ink pad (or the live canvas) sits above / captures Pencil input even when a modal dialog is open. Fix: while any dialog/sheet/menu is open, the ink pad and Lasso ignore input (input machine: modal open → idle, no ink), and dialogs are above every ink layer (z-index) with pointer-events; check all sheets (Name it, picture chooser, paste chooser, settings dialogs). e2e with Pencil pointer: open Name your page, tap Done → page renamed, zero strokes added.
3. **Pencil taps on in-page buttons type/ink instead of pressing them** (screenshot: tapping Keep mine / Use other / Keep both on the clash bar adds dots/commas "U. . . ' ' ." into the text box below; same family as item 2). With the Text tool, a Pencil tap lands in the editor (iPad Scribble / tap-to-type) instead of the button. Fix: every button, bar and chip rendered on the page (clash bar, picture strip, box bar, micro bar, chips, link cards) must take Pencil taps as clicks and stop them from reaching the editor, ink pad or Scribble (pointerdown on our UI = handled, preventDefault, no caret move; mark them `data-ui` so the input machine skips them). e2e with Pencil pointer for each.
4. **Hold menu goes off the page** (screenshot: Paste menu cut off at the bottom edge). Position it inside the visible area: flip above the point near the bottom, clamp left/right, account for the keyboard and Write pad.
5. **Hold menu pops up while writing with the Pencil (Scribble) in the Text tool.** A Scribble stroke starts with the Pencil resting still for a moment, which triggers our hold timer. Rules: with the Pencil, the hold menu opens only when the hold is ON or right next to the typing caret (within ~12 px) or on a selection; anywhere else a Pencil hold does nothing (it's writing). Cancel the timer as soon as the pen moves > 4 px or pressure/force rises, and never while iPad Scribble is active in the field. Finger holds keep working anywhere in text.
6. **Hold time too short.** Default to 1.5 s (setting range stays 0.6-3 s); show a small filling ring at the hold point after 0.4 s so the user sees it coming and can lift to cancel.
