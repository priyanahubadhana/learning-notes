# Owner bug batch (10 Nov 2026)

Collected from the owner's iPad pass; fix all in one go when the owner says so.

1. **Rectangle Lasso outline hard to see while dragging.** The live rectangle is a thin, faint dashed line on dark paper (screenshot: Stage 2 page). Make it clearly visible while selecting (stronger stroke, accent colour, light fill tint, both themes). After release the selection highlight is fine.
2. **Lasso can't start outside the text box.** Starting a Lasso loop in the page margin / area outside a box (left of the text, the blue-marked area in the screenshot) does nothing; the user must start inside the text block. The Lasso must start anywhere on the page surface (margins, gaps between boxes, outside boxes) and select whatever the loop covers. No drawing ink there unless that's already allowed; only the Lasso needs to start there.
3. **Undo/Redo unreliable (needs deep research + rework).** Often no Undo is offered after a real change (e.g. an accidental comma, a stray Enter, a mis-tap, a pen tap, a box/paper change). Every change of any kind must be undoable from the one Undo button, in order, across text, ink, boxes, pictures, tables, databases, page/notebook actions. Today there are separate histories (editor per box, ink, pad, page actions) and some changes bypass all of them. Also the history is too short: owner needs to go back 10-50+ steps. Research how Notion/GoodNotes/OneNote/Figma/tldraw do one unified history; design one app-level history with enough depth (e.g. 200 steps per page) and grouping.
4. **Version history too thin.** Page History has too few versions; a few edits later the needed version is gone. Keep many more snapshots (time-based + on big changes), compact old ones (hourly/daily), browse with preview and restore, per page; storage budget and limits per rules/scalability.md.
5. **Text still runs across the page gap.** In a long database/table-like list (All cards in this stage, 31 rows) the block crosses the gap between two A4 sheets, rows sitting in the gap. A row/line must never sit in the gap: lines and table/database rows continue on the next sheet. Owner also saw it right after an accidental edit (comma/Enter) that could not be undone.
6. **Accidental new text boxes near the page edge.** With the Text tool, tapping near the right edge while trying to scroll creates a new paper box (stray "Enter text or type '/' for commands" boxes at the right margin, overlapping the text). Need a safe margin zone along the page edges/scroll bar (like GoodNotes' wider dark border) where taps never create boxes; boxes only on a deliberate tap inside the page area; a tiny accidental box is removed automatically if left empty.
7. **Scroll bar for pages.** The page scroller needs a proper scroll bar: a visible track, a draggable thumb sized to the document, and up/down arrows (page up / page down, one sheet per tap) for slow, precise page-by-page movement; generous hit area that does not overlap the paper; balance between easy grabbing and no mis-taps.
8. **Restoring an old version doesn't restore the page layout.** Owner restored the first version in Page History (before the accidental text box existed) but the stray paper box was still there. A version must capture and restore everything on the page: blocks, paper boxes (Page.boxes, positions, sizes, locks), ink per box, pictures/sizes, page settings (paper style/size). Restore = the page exactly as it was, as one Undo-able step.
9. **Box creation model like GoodNotes (owner-approved idea).** Stray boxes appear on both left and right edges (screenshots: many "Enter text or type '/'" boxes stacked at the right margin). New rule: a new text box is made ONLY when the Text tool is selected AND the user taps blank paper. With any other tool, a tap on blank paper never makes a box (it deselects; with Pencil it switches back to the Lasso as GoodNotes does, per owner). Keep the safe edge margin from item 6 and auto-remove empty accidental boxes on leave.
10. **Placeholder text everywhere.** "Enter text or type '/' for commands" shows on every empty line/box at once, cluttering the page (screenshot 2). Show it only on the focused empty line (Notion style), never on unfocused empty lines or boxes.
11. **Tap model for boxes like GoodNotes (owner-approved idea).** With the Lasso (or any non-Text tool), the 1st tap on a text box selects the BOX (frame, handles, box bar) — no typing, no keyboard. Once the box is selected, a tap inside the text (any tool) places the caret exactly at the tapped point to edit; a double tap selects the word; a triple tap selects the line. Tapping outside deselects. With the Text tool, a tap inside a box edits directly. Must work with finger and Pencil, keep 44 px targets, and fit the tools state machine (no stuck states).
12. **Floating micro text bar while editing (GoodNotes style).** When the user starts typing in a box, don't switch the main tool bar to the Text tool; instead show one small floating bar next to the box: colour dot, size number (e.g. 26), font (Aa), B/I, align, list, highlighter, ⋯ more. Draggable, remembers its spot, compact (one row, ~44 px tall). We already have the mini bar and box bar: merge them into this one micro bar and use it for text editing everywhere; the full tool bar stays as is.
13. **Write pad: page doesn't follow the writing.** While writing in the Write pad (docked at the bottom, covering half the page), the live preview lands at the caret on the page (e.g. inside "The Claude app i|Ok|s Anthropic's...") but the page doesn't scroll, so the insertion point can be hidden behind the pad. Keep the caret/ghost text visible: scroll the page so the insertion line sits just above the pad (like typing with the keyboard does), on every update; respect the pad height when resized.
   - Correction (owner): scrolling once writing starts already works. What's missing: the page should scroll to the insertion point as soon as the Write pad OPENS (before writing anything), so the target line is visible above the pad from the start.
