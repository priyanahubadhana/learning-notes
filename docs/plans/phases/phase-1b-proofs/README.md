# The proofs for the notebook spec (26 Nov 2026)

**What this page is.** The facts that [the notebook spec](../../../features/claude-notebook.md) waited for (its list "For Opus to prove", section 8). They say what the app does today, what is new work, and where a spec line was wrong. The spec's sixth draft holds these facts.

**How they were made.** Four helpers (Opus) read the code. They changed nothing, ran nothing and signed in nowhere. Fable started them on 26 Nov, because the build's own list for that day did not name the proofs and the planning waited for them. Fable then checked the main claims of each report against the code. The code that was read: `main` at `fcc433f3` (the app code of the live version `7e53ae5d`). The code line `build/next` differs only by the fixes of #71 and #72.

**What these proofs are not.** They are not a look in the running app and not a test. Each point that needs one is in the list "Still to look at" below. The sizes are the helpers' estimates; the sized estimate for phase 1B is Opus's.

The four reports, with the file and the line for every claim:

- [The import and the Summary](import-and-summary.md)
- [The front page, the row of options and the phone](front-page-options-phone.md)
- [Shapes, pen marks and boxes](shapes-ink-boxes.md)
- [Locks, the tested cases and the fifteen faults](locks-and-faults.md)

## 2. Where a spec line was wrong or too weak

| Line           | What the spec said                                         | What the code says                                                                                                                                      |
| -------------- | ---------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------- |
| NB-41          | No format makes a whole notebook today.                    | The app's own notebook file does. What is missing is a form that Claude can write.                                                                      |
| NB-47          | Removing a whole notebook with one Undo is new.            | It exists. New is only that a notebook brought in is its own notebook and not a page in "Sources".                                                      |
| NB-57          | The tracker is a page of its own and lists top pages.      | It is an option of the notebook's own screen. One row for a top page is "one row for a chapter".                                                        |
| NB-75          | With the option off, Shapes does what it does today.       | Today an arrow in a narrow gap resizes the columns (#74) and a stroke on empty paper may not show (#75). "As today" can only mean with those two fixed. |
| NB-74          | A fault.                                                   | Drawing is a fault (the first box). Typing at the tapped place is new behaviour.                                                                        |
| NB-55          | "Signed in and in step."                                   | One more step on a new device: the passphrase or the recovery code.                                                                                     |
| NB-56          | A word never breaks letter by letter.                      | A style rule breaks a long word in a narrow box on purpose. Holding the line is new work.                                                               |
| NB-62          | "Saved" never shows while a stroke is not saved.           | "Saved" knows nothing of strokes that wait. New work, beside the fix of #72.                                                                            |
| NB-63          | The chosen tool is still chosen after a reload.            | The chosen tool is not saved. New work (#77).                                                                                                           |
| NB-54          | Reading text at least 15 px, a line at most 72 characters. | No such rule on a sheet today; the owner can set a smaller note size. The line can hold for what Claude writes and for the default look.                |
| The talk notes | "The four levels" are likely the tracker's column.         | They are Notebook, Subject, Topic, Page (owner, 16 Nov).                                                                                                |

## 3. Found on the way

- A page can be set to the paper size "Fit", but the reader of the notebook file takes only A4 and Letter. One such page would make the whole file refused. Not proven in the running app.
- "Add as copies" loses the Summary lines.
- The eraser takes a highlight off words only with the new Tool bar switched on. It is on by default on the preview and on the live app.
- No test changes the words of a card that exists.

## 4. Still to look at in the running app or on the iPad

For Opus (the running app, the preview):

1. A mark over words at another width of the box: does it stay on its words? Draw, then make the window or the box narrower. Draw at 160 percent, look at 100 percent. Draw with the browser's own zoom at 125 percent.
2. Pen ink over words: which lies on top (NB-88, #76).
3. Issue #75: a trace of which of the two paths makes the arrow vanish.
4. Issue #81: is the mind map cut, or does it scroll sideways, and at which width.
5. The faults that the code could not settle: the sticky box's width (#78), the Insert card (#80), the toast (#84), yellow on yellow (#85), the title shift (#86), the Lasso after a reload (#77).
6. A notebook file brought in with "Add as copies": do highlights, colours and ink land in the right place. Does the Undo bring everything back. Do the cards of a notebook in the Trash still show as due.
7. The "Fit" paper size and the notebook file.
8. How the Study tracker looks inside a page on the tablet.

For the owner's device (asked when its turn comes):

- The iPad upright and then sideways: do pen marks stay on their words.
- The phone: do the due cards show and can they be answered.
- Which box was made taller in the owner's try of 25 Nov: the first box of the page or a later one.

## 5. What the proofs open for the owner

Asked on 26 Nov and answered the same day: [the talk notes](../phase-1b-notebook-talk.md), section 5N, and the spec, section 8. In short: the shape gets its own room; an arrow from one text box to another comes after stage 1; the front page is a preset, a sheet made with the app's own features; both additions, yes.

1. A shape that holds text: does it get its own room in the text box, or may it lie over words that are there.
2. An arrow from one text box to another: in stage 1, or later.
3. The front page: a screen that the app arranges, or a free sheet.
4. Two additions to the one test (NB-01): an import never sets a lock; what the app counts is changed at its source.

The small sentences of Fable's went to the owner in a second round on 26 Nov and are answered (the talk notes, section 5O): the circle and the oval; a tap on a shape's border; what step one of the import carries; the row of options; "Continue reading" on all devices. The sentences that are still Fable's are listed in the spec, section 8.
