# D: locks, the NB-01 cases, NB-60 tests, the fifteen faults, NB-89 and NB-54

> One of the four reports behind [the proofs for the notebook spec](README.md) (26 Nov 2026). Read-only; made by a helper; the main claims were checked against the code by Fable.

Read-only fact finding, 26 Nov 2026. Working tree `C:\Users\pc\Downloads\learning-notes` (the main clone, at `fcc433f3`). Nothing was changed, nothing was run except `gh issue list` and `gh issue view`. Paths below are relative to the repo. A claim with no `file:line` is marked "not checked".

## Findings that change or contradict a spec line (read these first)

1. **NB-01 as written ("Claude does not lock what it writes") is not enough.** Today's backup bundle format accepts and copies lock flags: `locked`, `editLocked` and `readFirst` on notebooks and pages, `locked` on databases, boxes and ink layers (`src/share/checkRows.ts:92-94, 126, 149-151, 227, 481`; copied as `...rest` in `src/share/importBundle.ts:284-299`). If the new notebook import reuses that path, a file can arrive locked. NB-01 needs a rule on the importer side: "an import never sets a lock; lock flags in a file are dropped".
2. **A privacy-locked page with no lock set up shows normally** (`src/core/lock/lockService.ts:117`), but the moment the owner sets up a PIN later, every page that arrived with `locked: true` hides. Another reason for the import rule above.
3. **NB-01 "a highlight comes off with the eraser" holds today only with the switch `toolbar.v8` on.** With it off the default eraser leaves text highlights alone (`src/app/tools/main/inkSettings.ts:511-525`, proved by `e2e/toolbarV8Eraser.spec.ts:392`). `toolbar.v8` is on by default on the preview and the live host (`src/app/flags.ts:71-73, 99-103`), off on local and test hosts.
4. **Some things are locked by their nature and NB-01 cannot hold for them as worded:** Study tracker auto columns (Last revised, Cards due, Correct, Levels), formula, rollup and back-relation columns, the Card list, Day record and Page link blocks, Summary lines linked to a note line, and the content of an embed, a file or a book. NB-01 should name them as "worked out by the app; the owner changes the source, not the result" (list in point 1).
5. **NB-56 "a word never breaks letter by letter" contradicts a rule the code has on purpose:** `src/index.css:1278-1281` sets `overflow-wrap: break-word` so a word longer than a narrow box breaks. This is the cause of fault 7 as far as the code says. Holding NB-56 needs a box never narrower than its longest word, or smaller text, or hyphens: new work, and a choice for the plan.
6. **NB-62 "Saved never shows while a stroke is not saved yet" is new work.** The top bar's "Saved" only knows about failed saves (`src/app/saveStatus.ts:1-22`, `src/app/shell/status.ts:17-20`). `inkHasUnsaved()` exists (`src/ink/inkDoc.ts:64`) but nothing calls it. The late save itself is real: `src/ink/inkDoc.ts:203` pushes a 3-second timer over the 0.4-second one (`schedule`, `src/ink/inkDoc.ts:340-343`). Fault 4 = issue #72.
7. **NB-63 "the tool the owner chose is still chosen after a reload" is new work.** The chosen tool is kept in memory only (`src/app/tools/main/mainTools.ts:106`, `memStore`, `src/app/tools/store.ts:78-79`). It always starts as Text; why the owner's session showed Lasso is not settled from the code.
8. **NB-54 has no rule in the paper today.** The token `t-paper` (16 px, max 72ch) exists (`src/design/tokens.css:247-252`) but nothing uses it. The paper's text size can go down to 90 % of 16 px (14.4 px, `src/app/tools/main/textStyle.ts:15`) and a run can be set to 6 px (`src/paper/v2/oneBarModel.ts:11`). The sheet width follows the screen column and the zoom while the text size does not (`src/paper/PaperFrame.tsx:262-263`), so characters per line change with screen and zoom. NB-54 can only be a rule for what Claude writes and for the default look; the owner's own choices go below it.
9. **NB-89: a shared 44 px token exists but is not used everywhere.** `TOUCH_PX = 44` (`src/paper/safeGap.ts:17-24`), `--sh-hit: 44px` (`src/design/tokens.css:476`), `.ds-btn` min-height 44 (`src/design/tokens.css:344`). The global touch rule gives buttons only 32 px width (`src/index.css:312-316`). Known gaps: Summary line buttons 36 px (`src/app/summary/SummaryView.tsx:215, 226`), "Edit here" 36 px (`src/editor/PageEditor.tsx:320`), picture corner dots 24 px with a mouse (`src/editor/PictureHandles.tsx:526`), and issue #51 (four controls at 28-36 px).
10. **Fault 14 is the app's designed behaviour, not a bug in the code:** a pen pointer switches the device to Pencil mode with an Undo toast (`src/settings/deviceModeSettings.ts:258-279`, default `'pen'` at `src/settings/builtinSettings.ts:626`). That is why it has no issue. Whether the toast breaks NB-63 needs a look on the iPad.

## Point 5. NB-89 and NB-54: shared rules

**44-point tap target (NB-89).**

- Exists: `TOUCH_PX = 44` and `TOUCH_STYLE` (`src/paper/safeGap.ts:17-24`, used by the box grip, `src/paper/BoxFrame.tsx:301-321`); `--sh-hit: 44px` for the shell (`src/design/tokens.css:476`, used in `src/app/shell/shell.css` and `shell-parts.css`); `.ds-btn` min-height 44 (`src/design/tokens.css:344`); ink selection handles `size-11` = 44 px (`src/ink/InkSurface.tsx:744, 772`); a global touch rule: buttons min-height 44 but **min-width only 32** (`src/index.css:306-316`).
- Gaps: Summary line buttons 36 px (`src/app/summary/SummaryView.tsx:215, 226`); "Edit here" 36 px (`src/editor/PageEditor.tsx:320`); picture dots 24 px with a mouse, 44 px only on a coarse pointer (`src/editor/PictureHandles.tsx:526`); issue #51 (Sign in, theme buttons, Notes/Summary/Review 36 px, Add tag 28 px). A test exists: `e2e/touchTargets.spec.ts` (contents not checked).
- "Dots outside the shape": no shape that holds text exists yet (NB-80); for boxes and ink the dot placement was not checked.
- Missing: one token used by every control; a test that measures every tappable thing.

**Reading text at least 15 px and a line at most 72 characters (NB-54).**

- Exists: type scale `t-body` 15 px (`src/design/tokens.css:242-246`) and `t-paper` 16 px with `max-width: 72ch` (`src/design/tokens.css:247-252`), **but `t-paper` is used nowhere** in `src/`. The page column is `max-w-[720px]` with 56 px padding each side (`src/pages/PageView.tsx:540`).
- Contradicting the line: note size 90 % gives 14.4 px (`src/app/tools/main/textStyle.ts:15, 76`); a run size can be 6 to 200 px (`src/paper/v2/oneBarModel.ts:11-12`); the sheet width scales with the screen column and zoom while text size does not (`src/paper/PaperFrame.tsx:260-263`), so characters per line change with the device and the zoom.
- Missing: a rule that applies to what Claude writes and to the default look on a sheet, and a test that measures it on the tablet (both ways) and the PC.
