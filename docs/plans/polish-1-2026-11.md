# Polish pass 1 (7 Nov 2026), after Waves 3–4 and Sync

Opus review, Sonnet builds. Follows the master plan's "continuous polish" rule. The vision: "anubhav" learning (you learn by doing and recalling), GoodNotes-level Pencil, Notion breadth, Anki recall, and AI that you can fully edit and remove.

**Rules for the builder:**

- Build items in the order below. Each item is one commit with a CHANGELOG entry.
- Follow CLAUDE.md, `rules/building.md` and `rules/testing.md`.
- No new Dexie version, no new dependency, no stack change.
- Every new string goes in en, hi and es (`src/i18n/*W5p.ts`, a new trio of files).
- Every new tip goes in `src/help/helpRegistry.ts`, then regenerate `docs/HELP-TEXTS.md`.
- Log anything this plan does not decide in DECISIONS "Decisions to review".
- Add each owner check to the top of `docs/plans/owner-checks-pending.md`.

**Ideas borrowed (no art copied):**

- GoodNotes and Notability: every tool shows its options on press-and-hold, and controls work by touch, not hover.
- Things: very calm lists. One clear primary action, and swipe or long-press for everything else.
- Readwise: highlights flow into review on their own, with a daily "resurface" of a few highlights.
- Anki: honest numbers, and the default limits do not drown you.
- Session: one big, readable timer with a single Start control.
- Notion: one menu style everywhere ("⋯" and "/").

## The list (priority order)

### 1. One help-tip standard in every Wave 3–4 area

- **Problem:** Icon buttons in Home, Library, the readers, the picture editor, the mind map, Sync, Capture and Audio have no help tip. Some have only an `aria-label`, and some have native `title=`. So the bars look different and explain themselves differently.
- **Fix:**
  - Change every icon-only `<button>` in those folders to `IconButton` with `tip=` (`src/app/ui.tsx:34`). Add one registry entry per button, with short text (6–12 words).
  - Leave text buttons as they are.
  - Remove each native `title=` listed in the evidence. Replace it with `tip`, or with `aria-label` where the text is a page or book title (titles do not need a tip).
- **Files:**
  - `src/home/*.tsx`, `src/library/*.tsx`, `src/reader/**/*.tsx`, `src/images/*.tsx`, `src/editor/mindMap/*.tsx`, `src/sync/*.tsx`, `src/capture/*.tsx`, `src/audio/*.tsx`
  - the `app/` files listed in the evidence
  - `src/help/helpRegistry.ts`, i18n W5p
- **Tests:**
  - Extend `helpRegistry.test.ts`: every registered id has en, hi and es text.
  - Add a new unit test `help/noNativeTitle.test.ts` that scans `src/**/*.tsx`. It fails on ` title={` used on a `<button` or `IconButton`. Add an allow-list for `PopupHeader` and `RenameInput`.
  - Add one e2e: long-press an icon on Home shows a tip and does not run the action.
- **Owner check:** On the iPad, press and hold any icon on Home, in Library and in the picture editor. A tip appears, and it never stays stuck on screen.

### 2. Touch-reachable row actions (sidebar, Pages tab, task rows, library cards)

- **Problem:** Row icons appear only on hover or focus. On the iPad you must first tap a row (which opens it) to see them. GoodNotes and Things use a long-press or a ⋯ button instead.
- **Fix:**
  - On `(hover: none)` devices, always show one ⋯ button per row, 44 px hit area, at 60% opacity. Leave the hover behaviour as it is.
  - Long-press for 500 ms on a row (finger or Pencil) opens the same ⋯ menu. Use a shared hook `src/app/useLongPress.ts`; there is none today. A move of more than 8 px cancels the long-press.
  - Apply it to the sidebar rows, the D1 Pages tab, Home task rows and library cards.
- **Files:** `notebooks/Sidebar.tsx`, the Pages tab file under `app/` (D1), `home/` task row component, `library/` card component, new `app/useLongPress.ts` (+ test).
- **Tests:**
  - Unit test for `useLongPress`: timing, cancel on move, and no click after a long-press.
  - E2E on the `ipad-webkit` project (CI): at `hasTouch`, the ⋯ is visible without hover, and a long-press opens the menu.
- **Owner check:** Rename a notebook, a task and a book using only touch and Pencil, without a keyboard.

- **Fix:**

  2. Remove `'read'` from `PILL_TOOLS`, and delete `ReadOptions` and its i18n keys if no other file uses them.
  3. In `syncTool`, close the pill (`openPillTool.set(null)`) instead of opening `'read'`.
  4. Keep `'read'` in `MODE_TOOLS` (Reading mode stays a mode).
  5. `migrateApply.ts`: drop `'read'` from any saved pill state, and keep the saved tools.
- **Files:** `app/tools/main/mainTools.ts`, `PillContent.tsx`, `toolbarState.ts`, `migrateApply.ts`, the matching tests, i18n.
- **Tests:**
  - Update `toolbarState.test.ts`: the read set opens no pill.
  - Add a migration test: an old saved bar with an open `'read'` pill loads with no pill.
  - Run the existing reading e2e.
- **Owner check:** Turn Reading mode on and off from the ribbon and from the short bar. No empty pill appears, and the tab stays put (owner note 18).

### 5. Large data: Home, Tasks and Reports read by index

- **Problem:** The tables listed in the evidence are loaded whole. With years of timer entries, or 10,000 pages, Home opens slowly. This breaks `rules/scalability.md`.
- **Fix:**

  - Routines page picker: `db.pages.orderBy('updatedAt').reverse().filter(...).limit(300)`.
  - `taskService.listTasks`: use `where('status')`, or page through 500 rows at a time; keep the sort.
  - Habits and projects can stay whole (small by nature). Add a comment that says why.
- **Files:** `home/ReportsTab.tsx`, `home/Routines.tsx`, `core/taskService.ts`, `home/timerService.ts`.
- **Tests:**
  - Unit: seed 20,000 time entries; the report for one week reads at most that week's rows. Use a spy on `toArray` or a count.

- **Owner check:** None (the effect only shows with years of data). Note this in the CHANGELOG.

### 7. AI results: equal Undo and remove for every action

- **Problem:** Cards wait for approval, but summary and key points are written straight away, with only a toast Undo. Once the toast is gone, the only way back is "Remove this AI result" if the user knows it is there. The vision says AI must be fully editable and removable.
- **Fix:**
  - Summary and key points get the same preview sheet as cards: Apply / Edit first / Cancel. Reuse the approval dialog in `AiActions.tsx:202`.
  - Each AI batch shows a quiet "AI" chip on its blocks. The chip's menu offers "Remove this AI result" and "Keep as mine" (clears the mark).
- **Files:** `ai/AiActions.tsx`, `ai/aiRun.ts` (`applySummary`, `applyKeyPoints`), the block mark rendering in `editor/`, i18n.
- **Tests:**
  - Unit: applying, then removing, a batch leaves the page byte-equal to before.
  - E2E with the mock provider: summary preview → Apply → the AI chip → Remove; then key points → Keep as mine → no chip.
- **Owner check:** Make a summary with your own key, remove it, and make it again. Nothing is left behind.

### 9. Pencil friction in the picture editor and mind map

- **Problem:** The picture editor and the mind map came after the Pencil rules (A1–A3). Their handles and nodes are not checked against them: the 22 px handles, a Pencil tap that must not open the keyboard, and the palm touch that is ignored while the Pencil is down.
- **Fix:**
  - Corner handles and mind-map node handles get a 44 px hit area (the visible part stays small).
  - A Pencil tap on a node selects it, and a double-tap edits it. A finger tap edits it (like the text-tool rule).
  - While a pen pointer is down, ignore touch pointers (reuse the `penTap` guard).
- **Files:** `images/*` editor, `editor/mindMap/*`, `ink/` pen guard (import only).
- **Tests:** E2E (pencil-webkit project): pen pointer tap on a node does not focus an input; a touch during a pen drag is ignored; handle hit area ≥ 44 px.
- **Owner check:** With the Pencil, crop a picture and rearrange a mind map while your palm rests on the screen.

### 10. Decks and memory techniques: kinder defaults

  - Each memory template's first block is a short worked example in grey, marked as example text, with a "Clear example" button.
- **Files:** `recall/` deck settings, `memory/` templates, i18n.
- **Tests:** Unit: minutes estimate. E2E: a new PAO page shows the example, and Clear example empties it with one Undo.
