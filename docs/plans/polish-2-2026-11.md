# Polish pass 2 (8 Nov 2026): Pencil, bars, paper, recall, first run

Reviewer: Opus, after Rounds 5–7 and Phase Q steps 1–5. Docs only. Nothing here overrides an owner decision. Items marked **needs owner OK** change a decision and wait for the owner. The rest fit decisions already made.

## How we compare (short)

| Area | GoodNotes 6 / Notability / OneNote / Notion / Apple Notes | Us today |
| --- | --- | --- |
| Pencil tool switching | Double tap and squeeze follow the iPadOS setting (switch to the last tool, or to the eraser). GoodNotes users ask for a quick return to the last writing tool. Apple Notes and GoodNotes have a squeeze palette. | Safari never sees the Pencil double tap or squeeze. There is no "back to the last tool" button. |
| Toolbars | GoodNotes has one bar with pen presets (favourite pens with colour and size). Apple Notes has one small palette. | Main bar + options pill + detail card, Edit toolbar sheet (R7-11). There are no pen presets. The Lasso and selection rows are not on the new sheet yet (HANDOFF). |
| Lasso | GoodNotes: loop, then an action menu (convert, colour, resize, screenshot, copy). OneNote: Lasso across ink and containers. | Strong: filters, handles, twist, Convert to text, boxes (Q5). The menu order differs between ink and text selections. |
| Paper | Notability and GoodNotes: the paper is fixed, templates are picked at creation and a page thumbnail strip is shown. OneNote: containers appear on tap. | Q1–Q5 built: boxes on a tap, ink rules. Users can't easily tell that a tap makes a box. Paper style is chosen from the Pen pill. |
| Typing + handwriting | Apple Notes: Scribble in place, plus Smart Script tidies handwriting. OneNote: Ink to Text. Notability: typing in a text box on the page. | Write pad, Scribble, and Lasso › Convert to text. They are three separate entry points that new users won't find. |
| Review | GoodNotes 6 makes flashcards from notes and studies them in place. Notion has none. Anki: a daily queue with counts. | Decks, FSRS, Summary · Notes · Review (Phase M). Home doesn't show a daily "due today" nudge. |
| Onboarding | Notability opens a tutorial note and shows a tip the first time each button is tapped. Notion opens "Getting started" pages and its empty page says "Press / for commands". | There is no first-run flow at all (no onboarding code in `src/`). Device mode is picked silently and never picks Pencil. |

Sources: [GoodNotes feedback: auto-return to the last tool](https://feedback.goodnotes.com/forums/191274-customer-suggestions-for-goodnotes-apple/suggestions/50757209-smarter-auto-return-to-last-writing-tool), [GoodNotes: switching tools](https://feedback.goodnotes.com/forums/191274-customer-suggestions-for-goodnotes/suggestions/17877916-add-a-shortcut-to-switch-between-tools), [Apple: Pencil double tap](https://developer.apple.com/documentation/applepencil/handling-double-taps-from-apple-pencil.md), [Notability: Getting started](https://support.gingerlabs.com/hc/en-us/articles/4867633230234-Getting-Started-with-Notability), [OSU: Pencil Pro squeeze](https://techhub.osu.edu/news/2025/03/27/did-you-know-you-can-quickly-switch-apple-pencil-pror-tools-just-squeeze).

## The list (priority order)

Sizes: S = under half a day, M = about a day, L = 2+ days.

### 1. First-run welcome: three choices, then the app

- **Problem:** a new user lands with no guidance. Device mode is picked silently, Pencil is never chosen, and a new user doesn't learn the Pencil-first model (finger = UI, Pencil = content).
- **Evidence:** the Notability tutorial note; Notion's Getting started pages; R6-10; R7-14 ("a new user won't know").
- **Fix:** a one-time sheet with three steps: (1) "How will you write?" (Keyboard / Finger / Apple Pencil, which sets the device mode); (2) language and theme; (3) "Start with a sample notebook" or "Empty". Skip is always visible. It never shows again and can be reopened from Settings › Help.
- **Files:** new `src/app/onboarding/` (lazy chunk; first load has about 60 bytes spare, see O0), `settings/deviceModeSettings.ts`, `i18n/enO.ts`.
- **Tests:** an e2e first visit shows it, Skip writes nothing else, a second visit doesn't show it; existing e2e set the "seen" flag in their fixture.
- **Owner check:** clear the site data on the iPad, open the app, choose Apple Pencil: the bar is in Pencil mode and the sample opens.
- **Size:** M.

### 2. A "Start here" sample notebook

- **Problem:** the Write pad, Paper boxes, Layers, the Lasso and recall cards can only be found by exploring.
- **Evidence:** the Notability tutorial note; Notion's Getting started pages; the owner's discoverability notes (R7-14, R7-11).
- **Fix:** one built-in template notebook. It has five short pages, each with a "try it" line: write on paper, make a box, Lasso and convert, Write pad, make a card and review it. It is made from the existing template system and is an ordinary notebook that can be deleted.
- **Files:** `templates/` starter data, `i18n/enO.ts`.
- **Tests:** a unit test that the template is valid and that its cards exist; an e2e that it opens from item 1.
- **Owner check:** do every "try it" line on the iPad.
- **Size:** M.

### 3. First-use tips on tools (once each)

- **Problem:** tips exist, but they are hover/ⓘ only. On the iPad in Touch/Pencil mode, hover tips are off.
- **Evidence:** Notability shows a tip the first time each button is tapped; the help-and-tips spec.
- **Fix:** the first time Lasso, Write pad, Layers or a paper tap that makes a box is used, a small dismissible line shows near the pill ("Loop ink to select; tap a filter for text"). This reuses `HELP_LINES` and adds a seen-set per device. The existing Show help switch turns them off.
- **Files:** `help/Help.tsx`, `help/helpRegistry.ts`, `help/firstUse.ts` (new).
- **Tests:** registry test; an e2e where the tip shows once and not after a reload.
- **Owner check:** pick the Lasso for the first time: a tip shows; pick it again: no tip.
- **Size:** S.

### 4. "Back to last tool" button and a Pencil-friendly switch

- **Problem:** going Pen → Eraser → Pen takes two reaches to the bar. Safari can't receive the Pencil double tap or squeeze.
- **Evidence:** GoodNotes users ask for auto-return; Apple's double tap "switch to last used".
- **Fix:** (a) a small ⇄ "last tool" button on the main bar beside the tools (optional and pinnable, on by default in Pencil mode). (b) A setting, "Eraser returns to the previous tool after one erase" (off by default). Both use the existing `activeTool`.
- **Files:** `app/tools/main/mainTools.ts`, `editor/barActions.tsx`, `features/toolbar.md`.
- **Tests:** unit test of the last-tool memory; an e2e for Pen → Eraser → ⇄ = Pen.
- **Owner check:** Pen, Eraser, tap ⇄: you are back on the Pen with the same colour.
- **Size:** S.

### 5. Pen favourites (presets)

- **Problem:** changing colour and size takes the pill plus a card every time.
- **Evidence:** GoodNotes 6 favourite pens; GoodNotes feedback on "easier switching between pen colours".
- **Fix:** in the Pen and Highlighter pills, a row of up to 6 favourites (type + colour + size). Hold an option and choose "Save as favourite". They sync with the bar layout (R7-10 record).
- **Files:** `ink/` pen settings, the options pill, `sync/tables.ts` (no new table; this goes in the existing bar-layout record).
- **Tests:** unit test (save, order, limit 6); an e2e for tapping a favourite.
- **Owner check:** save a red fine pen, switch to blue, tap the favourite: red fine.
- **Size:** M.

### 6. Finish the Edit toolbar sheet: Lasso row and selection-bar rows

- **Problem:** HANDOFF says "Not done: Lasso row / selection-bar rows on the new sheet". The menus are inconsistent.
- **Evidence:** R7-11; polish-1 item 15 (one menu style).
- **Fix:** the same `EditListSheet` sections for the Lasso actions and the mini bar. The same order is used everywhere: Copy, Cut, Delete, Convert, Colour, Card, More.
- **Files:** `EditListSheet`, Lasso menu, selection mini bar.
- **Tests:** an e2e to reorder a Lasso action, then Done, then reload; the order is kept.
- **Owner check:** move Convert to text first in the Lasso menu.
- **Size:** M.

### 7. Scroll cue on the options pill

- **Problem:** this is HANDOFF's other leftover. The pill can overflow on narrow windows without showing a cue.
- **Evidence:** R7-14, R7-17.
- **Fix:** reuse the bar's chevron, count and handle on the pill.
- **Files:** options pill, the scroll hint helper.
- **Tests:** an e2e at 700 px width where the cue shows and the handle scrolls.
- **Owner check:** Split View, Pen pill: the cue shows and the handle drags.
- **Size:** S.

### 8. Paper: show that a tap makes a box

- **Problem:** the Q3 tap-to-box can't be seen until it's used. Users might think the empty paper is dead.
- **Evidence:** OneNote shows a container border on hover/tap; the owner's paper design (R7-9).
- **Fix:** the empty-paper state on a new page: the top box has a faint "Type, or tap anywhere on the paper to add a box" placeholder (first 3 pages only). The box outline shows while the box has focus. Nothing is stored.
- **Files:** `paper/` view, `i18n/enO.ts`.
- **Tests:** an e2e: a new page shows the hint, it goes after typing, and it is gone after 3 pages.
- **Owner check:** new page: the hint is visible; tap below: a box appears.
- **Size:** S.

### 9. Paper style at page creation and in the page ⋯

- **Problem:** the background (lined, grid, dots) and A4/Letter sit in the Pen pill, which isn't where users look.
- **Evidence:** GoodNotes and Notability ask for the paper when the note is made.
- **Fix:** add a "Paper" row (sheet, background) to the page ⋯ menu and to the new-page start (N2), keeping the Pen pill entry too. The default for new pages is set in Settings.
- **Files:** page menu, `features/new-page-start.md` flow, settings.
- **Tests:** an e2e: choose grid from the ⋯ menu and the sheet shows grid.
- **Owner check:** ⋯ › Paper › Grid.
- **Size:** S.

### 10. One "Handwriting to text" entry

- **Problem:** Scribble, Write pad and Lasso › Convert are three paths. Users don't know which one to use.
- **Evidence:** OneNote has a single Ink to Text; the Apple Notes Scribble is in place; R7-23 (the user won't understand the modes).
- **Fix:** Insert › "Handwriting" opens a tiny chooser that explains each path in one line: "Write in a pad (Write pad)", "Convert ink I already wrote (Lasso)", "Write straight into text (Scribble, iPad)". The tools stay as they are.
- **Files:** Insert pill, `i18n/enO.ts`.
- **Tests:** an e2e where each choice opens its tool.
- **Owner check:** Insert › Handwriting: three clear choices.
- **Size:** S.

### 11. "Due today" on Home and in the sidebar

- **Problem:** review relies on remembering to open All cards.
- **Evidence:** Anki's daily counts; GoodNotes 6 shows a study prompt on flashcard sets; the owner's vision (recall cards per notebook).
- **Fix:** a Home tile and a small count badge on the sidebar's Review row: "12 due · Start". One tap starts the All-cards session. The count is read from `scopeCounts` by index (polish-1 item 5 pattern).
- **Files:** `home/`, the sidebar, `recall/reviewService.ts` (read only).
- **Tests:** unit test of the count for 10,000 cards within budget; an e2e for the tile → review.
- **Owner check:** with due cards, Home shows the count and Start works.
- **Size:** S.

### 12. Make a card from a Lasso selection or a box

- **Problem:** handwritten notes can't become cards without converting first.
- **Evidence:** GoodNotes 6 flashcards from notes; wave 3B leftover "Make card from a tape or a picture".
- **Fix:** add a Lasso action, "Make card". The selected ink or picture becomes the card's answer as a picture (this reuses picture answers from E2), and the question is typed or written in the Name it sheet.
- **Files:** Lasso menu, `recall/`, picture answers.
- **Tests:** unit test of card creation from strokes; an e2e for loop → Make card → review shows the picture.
- **Owner check:** loop a handwritten formula, Make card, then review it.
- **Size:** M.

### 13. Empty states everywhere new users land

- **Problem:** an empty notebook, empty review, empty search and empty Layers each look different or blank.
- **Evidence:** Notion's empty page hint; polish-1 item 8 covered only Capture/AI.
- **Fix:** one `EmptyState` (icon, one line, one primary button) for: no notebooks, empty notebook, no cards ("Make your first card: select text › Card"), nothing due ("All done. Practise anyway?"), no search results, Layers gallery empty.
- **Files:** `ui/EmptyState.tsx` (new or the existing one), those screens.
- **Tests:** an e2e that each empty screen has a button.
- **Owner check:** new notebook: one clear next step.
- **Size:** M.

### 14. Pencil-first default when a Pencil is first seen (**needs owner OK**)

- **Problem:** in Touch mode the first Pencil stroke on an iPad stays in Touch mode unless Auto switch is on. "Pencil writes text" (Scribble) is off by default.
- **Evidence:** in Apple Notes the Pencil always draws and the finger scrolls; R6-10 (finger = UI, Pencil = content).
- **Fix proposal:** on the first Pencil contact, offer once: "Use Pencil mode? Finger for tools, Pencil for writing" (Yes / Not now). This changes the current device-mode defaults, so the owner decides.
- **Files:** `settings/deviceModeSettings.ts`, `app/deviceMode.ts`.
- **Tests:** an e2e with a pen pointer that shows the offer once.
- **Owner check:** a fresh iPad and a first Pencil touch.
- **Size:** S.

### 15. Speed: the first open of a paper page and the Lasso

- **Problem:** R6-11 lag. Paper adds one editor per box (Q3) and three ink canvases per screen. Many boxes could stall the iPad.
- **Evidence:** the paper-page plan §3; GoodNotes/OneNote stay smooth with hundreds of objects.
- **Fix:** mount box editors lazily when they come near the screen (a placeholder of the same height until then). Add a CI budget: 50 boxes and 2,000 strokes open in under 500 ms on chromium, and the Lasso selection over 50 boxes takes under 50 ms (median, as for the ink budget).
- **Files:** `paper/` view, `editor/boxScope.ts`, `e2e/` perf spec.
- **Tests:** the new budget spec; the full suite stays green.
- **Owner check:** open the biggest paper page and scroll: no stutter.
- **Size:** L.

## Not planned (and why)

- Shape recognition, a templates gallery for paper layouts, and AI tidying of handwriting: the first two conflict with the paper v1 owner defaults ("no Save as template"), and AI costs need the owner's OK.
- Pencil hover previews: Safari doesn't expose hover from the Pencil in the same way native apps get it, so it isn't reliable.
