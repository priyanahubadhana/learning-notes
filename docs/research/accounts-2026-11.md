# Accounts: email code, password, linking (9 Nov 2026)

Owner decision (9 Nov): accounts are required. Sign-in methods: Google, email + password, email code. A device stays signed in after the first time and keeps working offline. Searches below were run on 9 Nov 2026; points I could not confirm on an official page are marked "unverified".

## Findings

1. **Code beats link on an installed iPad web app.** A magic link opens in Safari, not in the installed web app, and the two do not share storage, so the person ends up signed in in the wrong place. Typing a code inside the app avoids that. On Android the link can work, but one flow for all is simpler. Source: [Progressier: magic links in a PWA](https://intercom.help/progressier/en/articles/10433517-can-you-use-magic-links-in-a-pwa) (third party; no Apple statement found, so test on the iPad).
2. **In Supabase a code and a link are the same call** (`signInWithOtp`); only the email template differs ("Magic Link" template shows `{{ .Token }}` for a code). Code length (6 to 10) and lifetime (default 1 hour) are Auth settings. Source: [Supabase passwordless email](https://supabase.com/docs/guides/auth/auth-email-passwordless), [Brevo on Supabase magic links](https://www.brevo.com/blog/supabase-magic-links/). Newer projects may default to 8 digits: set 6 explicitly.
3. **Passwords (NIST SP 800-63B-4, final July 2025):** a password used alone needs at least 15 characters; allow 64 or more; no composition rules (no "one capital, one symbol"); no forced rotation. Source: [Enzoic summary](https://www.enzoic.com/blog/nist-sp-800-63b-rev4/), [Sakimura](https://www.sakimura.org/en/2024/10/6443/) (secondary summaries; the exact wording is in section 3.1.1.2 of the standard, unverified here).
4. **Identity linking (Supabase):** accounts with the same verified email are linked automatically. `linkIdentity` (signed-in person adds a provider, OAuth redirect) needs "Manual linking" turned on in Auth settings (beta, off by default); `unlinkIdentity` needs at least two identities. Email OTP and password both belong to the single "email" identity. Source: [Supabase identity linking](https://supabase.com/docs/guides/auth/auth-identity-linking), [launch post](https://supabase.com/blog/supabase-auth-identity-linking-hooks). **Caution:** an advisory report says manual linking with unverified provider emails could allow account takeover ([ANT-2026-7WJV60DR](https://red.anthropic.com/2026/cvd/findings/ANT-2026-7WJV60DR)); whether it is fixed is unverified. We only link Google (which gives a verified email), and the allow-list hook limits who can have an account during testing.
5. **Email limits:** the built-in sender is for testing: about 2 emails per hour for the whole project, so a real sign-in will hit `over_email_send_rate_limit`. A custom SMTP sender is needed; Supabase then applies its own default limit (about 30 per hour, unverified) that is editable under Authentication > Rate Limits. One magic-link or code request per 60 s per user. Source: [Supabase testing auth flows](https://supabase.com/docs/guides/auth/testing-auth-flows.md).
6. **Free SMTP:** [Resend free](https://resend.com/docs/knowledge-base/account-quotas-and-limits): 100 emails/day, 3,000/month, one verified domain. [Brevo free](https://help.brevo.com/hc/en-us/articles/208580669): 300 emails/day, no time limit. Both need a verified sender (Resend needs a domain; Brevo can verify a single sender address).
7. **Connection screens:** Discord's Settings > Connections lists each linked service with a remove (X) and a Disconnect confirm ([Discord help](https://support.discord.com/hc/en-us/articles/8063233404823)). GitHub and VS Code were not reachable by search (unverified); from memory GitHub lists sign-in methods and linked emails in account security, and VS Code lists signed-in accounts in the Accounts menu with Sign Out. Common pattern used here: one row per method (name, the email it uses, one action), confirm before disconnecting, and the last method has no Disconnect.

## Recommendation (built)

- **Sign-in screen:** Continue with Google, Email code, Email + password (create, sign in, forgot password by code). Code entered inside the app (`autocomplete="one-time-code"`, 6 digits). Templates must show `{{ .Token }}` for Magic Link, Confirm signup and Reset password.
- **Passwords:** 15 to 128 characters, no other rules (NIST). Leaked-password checking is a paid Supabase feature (unverified), so the code is the safer default; a password is optional.
- **Staying signed in:** refresh tokens (already how the session works). Set Auth > Sessions: no time-box and no inactivity timeout, so the device stays signed in. Offline use never calls the server.
- **Connected accounts:** list Google, Email code and Password with their emails. Connect Google (`linkIdentity`, needs manual linking on). Disconnect Google or the email identity only while the other remains. A password can be changed but not removed (Supabase has no remove; the row says so).
- **Testing allow-list kept:** the app still refuses any email except the owner's, and the server hook refuses other new accounts. This is a launch-checklist item.
- **Honest limits:** Drive's lasting connection needs Google linked (the email sign-in has no Google token). A new account with a code needs the SMTP sender or the 2-per-hour built-in limit will block it.
