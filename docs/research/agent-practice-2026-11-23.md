# Agent practice, November 2026 (task M7, phase 1A)

**What this is:** one short web pass (eight standard searches, 23 Nov 2026) on how Anthropic and Google run coding agents today, compared with what we do (docs/HOW-WE-BUILD.md sections 2 and 6, and phase 1M). Findings to fold into M0. **Limits:** read from the search-result excerpts of each page, not full page reads; vendor pages change, so check the page before turning a line into a rule.

## Fold into M0 (at most eight)

1. **Keep** one task per fresh window under 100K (findings 1, 7, 11). Against: every window re-reads its files, a fixed start-up cost per task.
2. **Keep** the fresh checker that sees only the diff and the spec (findings 4, 11). Against: one more window of tokens on every normal part.
3. **Try** a Stop hook on builder windows that runs the fast checks and exits 2 while red (finding 3). Against: a flaky test can trap the builder in a loop, so it needs a try limit.
4. **Try** `autoCompactWindow: 100000` in the builder definition, so the 100K plan is a setting, not a hope (finding 1). Against: compaction at 100K may cut detail a builder still needs; the 1M numbers should show it is rare.
5. **Try** scoping the builder's and reviewer's `tools` lists to what they use (finding 2). Against: a missing tool stalls a builder and costs a retry.
6. **Try** two brief lines: the report format and the expected effort (finding 6). Against: pushes the brief toward the 200-word limit.
7. **Try** each new try after a failure in a fresh window that carries the written lessons (finding 5). Against: in-window evidence is lost unless the builder writes it down first.
8. **Drop** more parallel builders or agent teams for now (findings 6, 8). Against: wall-clock time stays slower than a team could reach.
