# AI cost audit (11 Nov 2026)

Goal: no feature can spend the owner's (or a user's) money unexpectedly. Scope: every path that can reach a paid API (`src/ai`, `src/prompts`, `src/share/notebooklm`, `src/editor/cleanupAi.ts`, `src/editor/writePad/AiCanvas.tsx`, settings sync, key sync). The only paid network calls in the app are the three AI providers (Anthropic, OpenAI, Gemini) through `callAi` and `testKey`. Everything else the app contacts (Supabase, Google Drive, the free dictionary) is free-tier or free. There is no background, scheduled or automatic AI run anywhere: every call starts from a tap.

## Findings and fixes

| #   | Path                                                                                                        | Risk                                                                                                                                                                                                                                                     | Fix (done)                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| --- | ----------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | `callAi` (used by prompts, skills, fact check, clean-up, Ask book, Convert ink, pad read, mind map rebuild) | HIGH. The "AI is on" switch was checked only by some callers (`runAi`, `runVision`, the screens). `callAi` itself never looked, and a screen could hold an old config after AI was switched off (or sync turned it off). A test even passed with AI off. | `callAi` refuses when the config says off or when `ai.enabled` is off right now (read live, again just before each model is tried). Test: `aiCost.test.ts` "AI off is off inside callAi".                                                                                                                                                                                                                                                                                  |
| 2   | Two calls started together (double tap, two screens)                                                        | HIGH. The cap check read the recorded spend only; spend is recorded after the answer, so two calls started together both passed the same check and could together pass the cap.                                                                          | Each running call reserves its worst-case cost on its key; the cap check counts the reservation. Test: "two different calls started together cannot both slip under the cap".                                                                                                                                                                                                                                                                                              |
| 3   | Double tap / re-render on one action                                                                        | MEDIUM. Summarise, Key points, Cards, Make cards, Convert, Test key set their busy flag only after an await, so a second tap could send the same paid call twice.                                                                                        | An identical request (same words, pictures, limit, models) already running is shared, so it is paid once (`callAi`, `testKey`). Taps on AiActions and Make cards are also blocked by a ref set on the first tap. Test: "an identical request already running is shared".                                                                                                                                                                                                   |
| 4   | A shared key on several devices (key sync)                                                                  | HIGH. The spend counter lives on each device, but the key and its cap sync. Three devices meant three times the cap.                                                                                                                                     | With key sync on, each device writes its monthly use to its own `aiUsage` secret record (end-to-end locked like the keys, no key inside) and every device adds the others' use to the cap check. Test: "a shared key is capped as one key across devices".                                                                                                                                                                                                                 |
| 5   | Costly single calls with no cost shown (any caller)                                                         | MEDIUM. Prompts, skills, clean-up, Ask book and the mind-map rebuild show a cost first; nothing stopped another caller, a fallback model or a future screen from sending a very costly call unseen.                                                      | New central rule: a call whose worst case is above US$0.10 (about 9 rupees) is refused unless the screen passes the cost it showed (`approvedUsd`). Every cost-showing screen now passes it; a pricier fallback model is skipped, not silently used. The one-tap actions (page text capped at 30,000 characters, picture capped at 1,568 px) cannot reach the limit even on the dearest model. Test: "refuses a worst case above the limit unless the screen approved it". |
| 6   | Timeout, then fallback                                                                                      | MEDIUM. A request that timed out after 90 s was treated like a connection failure, so the next model was asked as well. The first may have been processed and billed: two charges for one answer, only one (or none) recorded.                           | A timeout is marked `maybeBilled`: it is never sent to another model, and the words sent are counted in the usage. Test: "a timed-out request is counted once and not sent to another model".                                                                                                                                                                                                                                                                              |
| 7   | Streaming (Ask book, Story so far) that drops part way                                                      | MEDIUM. The error threw away the words already received and the usage was not recorded, so the money was spent but the cap did not see it.                                                                                                               | The words that came are kept (shown as stopped) and counted. Test: "a stream that drops after some words keeps them and counts them".                                                                                                                                                                                                                                                                                                                                      |
| 8   | Settings › AI › Test key                                                                                    | LOW. It ignored the cap and a double tap made two calls.                                                                                                                                                                                                 | The cap holds for it and a double tap makes one call. Test: "the key test is capped and a double tap makes one call". It still works while AI is off (see DECISIONS).                                                                                                                                                                                                                                                                                                      |

## Checked and fine (no change)

| Path                                 | Why it is safe                                                                                                                                                                                                                         |
| ------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Two settings enabling the same call  | None. A call needs ALL of: Settings › AI on (`ai.enabled`), a key, the notebook's Allow AI (library books skip only this one), the privacy OK, the lock rule, and the cap. They are ANDed, never ORed.                                 |
| Auto-run / background / scheduled AI | None exists. Every call starts from a button (Summarise, Key points, Cards, Run, Send, Convert, Read, Clean up, Rebuild, Fact check, Test). No effect, timer, visibility or sync handler calls `callAi`.                               |
| Sync of a "run" flag                 | None is synced. Synced AI values are choices only (`ai.enabled`, `ai.cap`, `ai.privacyOk`, `ai.modelOrder`, `ai.modelKeys`) plus the opt-in key record. Nothing triggers a call on arrival.                                            |
| Retries                              | `providers.post` retries at most twice, only on 429, 5xx or a dropped connection, and the usage is recorded once for the call that succeeded. Streaming has no retry. The providers do not bill a request they answer with 429 or 5xx. |
| Fallback order                       | Only the user's own model order (Settings › AI model cards). Each fallback key has its own cap check. A notebook with its own choice never falls back (existing rule).                                                                 |
| Cost shown first                     | Prompts, skills, fact check (second model), clean-up, Ask book (Send), mind-map rebuild: yes. One-tap actions: below the limit by construction (see #5).                                                                               |
| Spending limit                       | Per key (or the default) per calendar month, checked with the worst case (prompt + pictures in, the whole answer limit out) before each model is tried.                                                                                |

## Not changed (judgement, see DECISIONS)

- Key sync off: two devices that each typed the same key by hand cannot know each other's spend, so each device has its own cap. The app cannot fix this; key sync (Settings › AI) is the way to share one cap.
- A synced `ai.enabled` turns AI on for the other devices of the account (they also need a key). Kept: it is what the owner chose in the sync groups.
